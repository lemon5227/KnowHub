# Enterprise evaluation v1

User approved retrieval and workflow evaluation before this spec. Extend evaluation only, not product behavior.

- Author/freeze 60 Chinese queries and a synthetic SOP corpus before observing retrieval. Each query references exact source/section relevance judgments. Include semantic paraphrases, identifier queries and multi-evidence questions. All relevant evidence must be retrieved for a strict multi-evidence hit.
- Use the existing ingestion/chunking, real multilingual-e5-small CPU inference and PostgreSQL/pgvector. Evaluate lexical, dense and hybrid using production search(k=8), report macro Recall@1/3/5/8, Hit@5, AllEvidence@5 and MRR@8. The product caps k at 8, so no Recall@10. Measure per-query latency including database and query embedding, excluding initial model loading/index construction. No tuning on these queries.
- Freeze 24 workflow cases before model execution. Every case has its own initial synthetic order/ticket. Use real Agent/Model/Store; no mock model, no privileged hints in prompts, no reruns for higher scores. New evaluation authorization covers at most 96 API calls, 4/case, 1200 output tokens/call; temperature 0. Existing completed validation and Kage budgets are separate. Failed requests count toward budget; stop on quota/auth failure.
- Objective task checks include required factual output, observed tools, requested proposal, valid citations where needed, uncertainty, and zero writes before approval. Check real approve/reject + repeat decisions on valid proposals. Mechanical results require manual semantic review; no claim that token matching proves truth or complete grounding.
- Dedicated database name must be knowhub_benchmark; no truncation of demo/test DB. Save partial raw records after every case; no secrets. Freeze hashes, versions, environment, all ranks/scores, tokens, latency, successes/failures. Reuse benchmark at most for transparent diagnostics, not held-out generalization claims.
- Publish report with denominators, uncertainty intervals, synthetic/author-created/single-pass limits; measured regressions remain visible. Update README and AI resume only with supported data. Keep personal Git identity and separate dataset, harness, results commits.
